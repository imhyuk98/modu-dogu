# 친구 공유 콘텐츠 1차 구현

## 구현 범위

| 경로 | 기능 | 결과 |
|---|---|---|
| /tools/friendship-quiz | 본인이 8개 정답 선택 → 친구가 추측 | 정답 수와 문항별 비교 |
| /tools/friend-manual | 본인 닉네임으로 초대 → 친구가 긍정적 설명 5개 선택 | 한 친구가 작성한 사용 설명서 |
| /tools/friend-chemistry | 각자 본인의 취향 8개 선택 | 취향 일치율·문항별 비교; 기존 answers 초대 주소 호환 |
| /tools/compliment-card | 본인 초대 → 친구가 상·고마움·다음 활동 선택 | 칭찬 카드 |
| /tools/moon-compatibility | 두 닉네임·생일 입력 | 8단계 달 모티브 두 개와 창작 관계 문구 |

공통: 모바일 입력, 초대 또는 결과 주소 공유, 결과 이미지 저장(스토리/정사각형), 관련 콘텐츠 연결, 기본 SEO 메타데이터와 도구 목록 등록.

## 중요한 제한

- 정적 사이트 안에서 동작. 답변을 수집하는 서버, 자동 알림, 실시간 점수판, 다중 응답 보관함은 없음.
- 친구가 완성한 결과 링크를 원래 보낸 사람에게 직접 전달해야 함.
- 닉네임과 선택은 URL fragment에 포함. 암호화/위변조 방지가 아니며 링크 소지자가 읽거나 바꿀 수 있음. 우정고사 정답도 기술적으로 열람 가능하므로 공정성이 필요한 시험에 사용하면 안 됨.
- 생일은 메모리에서 계산하고 결과 생성 후 입력 상태에서 지움. 결과 주소에는 생일 대신 0~7 달 유형과 닉네임만 포함.
- 링크 분실 복구·개별 링크 회수 불가. 민감한 정보 수집과 자유서술 익명 비난을 피함.
- 달은 평균 29.530588853일 주기와 2000-01-06 기준의 근사 모티브. 정밀 천문력, 실제 궁합, 성격 진단이 아님. 출생 시각과 지역 미반영.
- 소셜 미리보기는 도구별 전용 OG 이미지 5종. 개인별 결과는 링크를 열거나 저장한 결과 이미지에서 확인.
- 배포는 별도 작업. 이번 구현 자체로 운영 사이트가 바뀌지 않음.

## 측정

선택적 분석 동의 시 기존 trackEvent 사용. 이벤트에 닉네임·생일·답변·초대 원문을 넣지 않음.

| 이벤트 | 의미 |
|---|---|
| tool_start | 입력 시작; flow=create 또는 invite |
| invite_create | 초대 링크 생성 |
| result_share | 기존 공유 컴포넌트의 공유/복사 동작; 수신자에게 실제 전달됐다는 보장은 아님 |
| invite_open | 유효 초대 링크 열기 |
| invite_complete | 친구의 답변 제출 |
| tool_complete | 초대 생성 또는 답변 완성; flow로 분리. 달은 카드 생성 |
| shared_result_open | 유효 결과 링크 열기 |
| result_image_save | 결과 이미지 저장 동작 |
| return_visit | 기존 방문 추적에서 제공 |

이벤트 수는 사람 수가 아님. 초대 ID를 분석으로 보내지 않으므로 초대 한 건별 연결 분석은 제공하지 않음. GA4에서 tool과 flow로 분리하고 사용자/세션 단위의 기간·분모를 통일할 것. 기존 운영 대시보드의 새 이벤트 전용 차트는 이번 범위에 포함하지 않음.

## 디자인·SNS 공유 개선

- Stitch의 종이 퀴즈 콘셉트를 참고해 한 화면 한 문항, 진행률, 이전/다음, 제출 전 수정 흐름으로 구성.
- 결과 PNG는 9:16 스토리와 1:1 피드 지원. 실제 저장 파일을 화면에 미리 보여주며, QR은 개인정보 없는 놀이 시작 화면으로 연결.
- 이미지 공유는 미리 준비한 파일을 전송. 미지원·취소·실패를 구분하고 저장 후 수동 게시 안내 제공. 링크 복사는 별도 동작.
- 친구의 결과는 원래 보낸 사람에게 링크로 직접 전달해야 함. 자동 수신함 없음.
- 카카오 전용 공유는 `NEXT_PUBLIC_KAKAO_JS_KEY` 설정 전 숨김. 공용 지도 키나 Admin/REST API 키를 대신 사용하지 않음.
- 카카오 설정: 개발자 콘솔의 앱 → 플랫폼 키 → JavaScript 키에서 키 확인 및 JavaScript SDK 도메인 등록. 제품 링크의 웹 도메인도 설정. 운영 도메인 `https://modu-dogu.pages.dev`, 로컬 테스트는 `http://localhost:3000` 사용.
- 키는 빌드 시 반영되므로 설정 후 재빌드·배포 필요. SDK는 전용 공유 준비 버튼을 누를 때만 로드.
- 카카오 호출 테스트는 모의 SDK 기반이며 실제 전송 성공을 증명하지 않음. iOS Safari·Android Chrome·카카오 인앱에서 링크 열기, 전송/취소, 이미지 저장·게시를 실제 기기로 확인해야 함.

## 검증 실행

### 2026-09-08 SNS 확장

- 후속 UX 변경: LINE·인스타그램은 중립 배경 + 브랜드 색상 아이콘으로 정리. 문항 선택 후 240ms 뒤 자동 이동하며, 이동 대기 중 중복 입력을 잠금. 이전/이탈 시 타이머 취소. 검토 화면에서 답을 수정하면 검토 화면으로 복귀. 마지막 답은 자동 제출하지 않고 사용자가 완성 버튼으로 확인.

- 카카오톡·X(트위터)·LINE·인스타그램을 별도 버튼으로 표시. X/LINE은 클릭할 때만 공식 공유 작성 화면을 열고, 차단 시 다시 열기 링크 제공. 별도 SNS SDK를 추가하지 않음.
- 인스타그램 버튼은 이미지 저장 → 링크만 복사 → 스토리 링크 스티커/DM 안내. 자동 게시나 자동 이미지 첨부를 약속하지 않음.
- 링크에 담긴 닉네임·선택 정보는 외부 SNS에 전달됨. 공개 게시 전 공개 범위 확인 안내.
- `share_request_{kakao,x,line,native,sms}`는 요청 건수. `instagram_guide_open`, `instagram_link_copy`, `share_link_copy`는 준비·복사 동작. 전송 성공으로 해석하지 않음. 기존 `share_request` 합계와 채널별 이벤트를 더하면 중복됨.
- 운영 대시보드의 ‘SNS 공유와 친구 참여’에서 위 이벤트, 초대 생성/열기, 친구 답변 완료, 결과 재열기, 이미지 저장, 재방문을 별도 행으로 표시. 기존 포털·첫 방문 페이지 필터 공유. 사용자 수를 행 간 합산하거나 이벤트 건수 비율을 순차 퍼널로 해석하지 않음.
- 새 채널별 이벤트는 배포 이후 수집. 과거 기록을 소급 생성하지 않음. 수신자가 어떤 SNS에서 왔는지는 GA4 원본 출처가 제공하는 범위에서만 확인 가능하며 발신 버튼과 수신 방문을 연결한 기여도는 아님.
- 참고: https://docs.x.com/x-for-websites/web-intents/overview 및 https://developers.line.biz/en/docs/line-social-plugins/install-guide/using-line-share-buttons/
- 실제 휴대폰 확인: iOS Safari/Android Chrome에서 카카오·X·LINE 전송/취소 → 받은 초대 답변 → 결과 다시 보내기. 인스타그램 이미지 저장·스토리 링크·DM 열기 확인. 카카오 앱 이름 변경은 새 메시지로 확인. 자동 검사는 실제 앱 전송을 대신하지 않음.
- 배포 확인: `https://f164bf4d.modu-dogu.pages.dev` (운영 별칭 `https://modu-dogu.pages.dev`). 단위 검사 27개, 운영 5개 콘텐츠 브라우저 검사, 운영 경로 8개·OG·키 반영 검사 통과. 화면 폭 320/390/1280, 명암 대비, 인스타그램 복사 거부, X/LINE 작성 주소, 비동의 시 이벤트 차단 검증. 실제 SNS 전송은 모의 호출로 대체했으므로 실기기 확인 필요.
- 대시보드는 기존 로컬 설정으로 `http://127.0.0.1:8788`에서 실행. 인증 및 실제 GA4 사용 보고서 확인. Cloudflare 대시보드 Worker는 계정에 없어 새로 배포하지 않음. Search Console은 기존 권한/API 설정에 의한 403 상태이며 SNS/GA4 조회와 분리됨.
