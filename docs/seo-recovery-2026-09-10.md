# 검색 유입 복구 1차 변경 — 2026-09-10

## 범위와 근거

9/4 커밋 f591a2d가 숫자별 계산 결과에 일괄 noindex를 추가했다. 8/11–9/3 GA4 조회에서 이 중 25개 URL에 랜딩 세션 195건이 관측됐다. 현재 로컬 분석 원본은 docs/audits/2026-09-10/ga4-noindex-impact.json에 있으며, 비공개 분석 폴더는 Git에 포함되지 않는다.

복구 명단은 lib/calculator-result-indexing.ts에 명시적으로 보관한다. 25개는 BMI 4개, 대출 8개, 전월세 4개, 퇴직금 5개, 실업급여 4개다. 각 페이지는 조건별 결과와 설명·산출 내역이 있는 기존 정적 페이지이며 새 조합을 양산하지 않는다. 기존 트래픽은 복구 우선순위의 근거이지 검색 품질·순위의 보장은 아니다. 연봉 결과는 이 관측 구간에 유입이 확인되지 않아 복구 대상에 넣지 않았다.

## 변경

- 검토한 25개만 index,follow와 자기 URL canonical을 설정.
- 나머지 756개 계산 결과는 noindex,follow와 부모 canonical 유지.
- 친구 결과함과 게임 결과 페이지의 검색 제외 유지. 개인정보·측정 동의 정책 변경 없음.
- 사이트맵에 25개를 복구해 총 196개. 실제 변경한 페이지에만 lastmod를 갱신하며, 변경되지 않은 날짜는 유지.
- 다섯 부모 계산기에 조건별 예시 링크 제공. 사이트맵뿐 아니라 정적 HTML 링크로도 복구 페이지에 접근 가능.
- 메타데이터 정리 스크립트의 일괄 noindex 삽입 및 결과 URL 일괄 삭제 로직 제거. 사이트맵 생성과 메타데이터는 동일한 허용 목록을 사용.
- 환율 페이지는 로딩·API 실패 중에도 설명, 사용법, FAQ, 관련 도구를 HTML로 제공. 실제 환율이 없으면 임의 숫자나 0원 결과를 표시하지 않음.
- CI에 SEO 출력 검증과 환율 로딩/성공/실패 브라우저 검증 추가.

## 검증 방법

1. npm run build
2. npm run qa:seo — 실제 출력에서 196개 사이트맵의 canonical/noindex, 25개 복구, 756개 제외, 개인정보 결과 제외, 부모 링크, 환율 초기 본문 검사.
3. npm run qa:static — 전체 960 HTML 및 내부 참조 검사.
4. node scripts/exchange-render-smoke.mjs — Chrome 디버거 9224를 이용해 격리된 컨텍스트에서 환율 API 응답을 모의 처리. 로딩/정상 계산/금액 입력/모바일 폭/실패 안내를 검사. 실제 외부 API 및 측정 요청은 전송하지 않음.
5. npm run lint, npm run qa:calculations, npm run qa:security.

사이트맵을 다시 만들 때 실제로 변경한 URL은 SITEMAP_UPDATED_PATHS에 쉼표로 구분해 지정한다. SITEMAP_DATE는 해당 수정 날짜를 지정한다. 지정하지 않은 기존 페이지의 날짜는 보존된다.

## 운영 반영 후 확인할 것

로컬 검증 결과: 프로덕션 빌드와 TypeScript 검사, 전체 lint 및 추가 스크립트 lint, 계산·보안 회귀 검증 통과. 정적 출력 960개에서 끊어진 대상 0개, 형식 오류 0개. SEO 출력 검증에서 사이트맵 196개·복구 25개·제외 유지 756개·부모 링크 25개·비공개 제외·환율 초기 본문을 확인했다. 환율 브라우저 검증도 로딩·모의 API 성공/입력·모바일 가로폭·API 실패 안내 모두 통과했다.

이 문서는 코드 수정 기록이며 배포 완료 또는 실제 재색인 완료를 뜻하지 않는다.

1. 배포된 사이트에서 아래 예시의 index,follow + 자기 canonical 및 사이트맵 포함 확인:
   - /calculators/rent-conversion/10000-1000-5
   - /calculators/unemployment/35-3-300
   - /calculators/bmi/180-75
2. /calculators/salary/3000 및 /tools/friend-inbox는 계속 noindex인지 확인.
3. 서치어드바이저에서 복구 대상 URL의 수집 여부·색인 가능 여부·색인 여부를 각각 확인. 검사 화면에 갱신 시각이 있으면 함께 기록.
4. 재색인이 확인된 이후의 네이버 노출·클릭을 같은 길이/요일의 구간으로 비교. 아직 재색인되지 않았다면 효과가 없다고 단정하지 않음.
5. 전기요금의 기존 노출 감소와 GA4의 동의 전후 측정 범위 변화는 별도로 분석. 이번 복구로 전체 감소가 해결됐다고 해석하지 않음.

검색엔진의 재수집·색인 여부와 순위는 보장할 수 없다. 복구 범위는 후속 데이터를 보고 조정하며 781개를 일괄 색인 허용하지 않는다.
